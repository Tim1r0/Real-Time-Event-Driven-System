# Real-Time Event-Driven System

Система обработки тяжелых задач с архитектурой микросервисов и уведомлениями в реальном времени.

##   Основной функционал
- **Asynchronous Task Processing**: Прием "тяжелых" задач через API и моментальный ответ пользователю.
- **Microservice Architecture**: Разделение ответственности между API-сервисом и Worker-сервисом.
- **Real-Time Notifications**: Использование WebSockets для мгновенного уведомления клиента о завершении задачи.
- **Event-Driven Bridge**: Связь между сервисами через брокер сообщений (RabbitMQ) и шину событий (Redis Pub/Sub).

## Технологический стек
- **FastAPI**: Современный асинхронный веб-фреймворк.
- **TaskIQ**: Распределенная очередь задач для Python.
- **RabbitMQ**: Брокер сообщений для передачи задач воркерам.
- **Redis**: 
    - *Result Backend*: хранение статусов задач.
    - *Pub/Sub*: трансляция событий из воркера в API.
- **Docker & Docker Compose**: Контейнеризация всей инфраструктуры.
- **Pydantic Settings**: Управление конфигурациями через переменные окружения.

##  Архитектурная схема
1. **Client** отправляет POST запрос на `/process/`.
2. **API** упаковывает задачу и отправляет её в **RabbitMQ**.
3. **Worker** забирает задачу из очереди и выполняет её в фоновом режиме.
4. По завершении **Worker** отправляет сигнал в **Redis Pub/Sub** канал.
5. Фоновый слушатель (**Redis Listener**) в API-сервисе ловит сигнал.
6. **API** находит активное **WebSocket** соединение пользователя и отправляет уведомление.
